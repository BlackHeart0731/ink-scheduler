# Ink Scheduler

Discord に、決めた日時でメッセージを自動投稿するツールです。**ボットは作りません。** Discord の「Webhook」だけで動き、自分のサーバー（自宅の PC や小さな常時稼働マシン）で動かします。

- 1回だけ / 毎日 / 毎週 / 毎月（月末にも対応）/ 毎年 の予約投稿
- 誕生日の自動お祝い（月日だけ保存。2月29日生まれは、うるう年以外は2月28日に送ります）
- 送信先（Webhook）を名前つきで複数登録し、予約のときにプルダウンで選べます
- 停止していて送れなかった分の扱いを、予約ごとに選べます（確認通知 / 遅れて送る / スキップ）
- 管理画面（ブラウザ）から全部操作できます。パスワードも画面から変えられます
- 毎日の自動バックアップ。画面から、ダウンロードと復元もできます

## 仕組み

コンテナが2つ動きます。どちらも同じ `data/scheduler.db`（SQLite）を使います。

| 名前 | 役目 |
| --- | --- |
| `sender` | 30秒ごとに「送る時刻になった予約・誕生日」を探して Discord に送ります。毎日1回の自動バックアップもここです |
| `admin` | 予約・誕生日・送信先・設定を編集する管理画面です（Streamlit） |

予約は `sender` が動いている間だけ送られます。マシンを止めている間の分をどうするかは、後ろの「止まっていた間の扱い」を見てください。

## 必要なもの

- Docker と Docker Compose
- 24時間つけっぱなしにできるマシン（Linux の小型 PC など。普段使いの PC でも、つけている間だけなら動きます）
- 投稿したい Discord チャンネルの Webhook URL（チャンネルの設定 → 連携サービス → ウェブフック で作れます）

## 導入

```
git clone https://github.com/BlackHeart0731/ink-scheduler.git ink-scheduler
cd ink-scheduler
cp .env.example .env
```

`.env` を開いて、必要なところを書き換えます（全部の項目の説明は `.env.example` の中に書いてあります）。

```
docker compose up -d --build
```

最初のビルドは数分かかります。終わったら、ブラウザで `http://localhost:8501` を開きます。

> `sudo` が必要な環境では `sudo docker compose …` にしてください。

### パスワード

- `.env` の `INK_SCHEDULER_PASSWORD` が、パスワードの初期値です（英数字だけ）。空のままだと、パスワードなしで開けます。
- 管理画面の「設定」タブ → 「管理画面のパスワード」で、あとから好きなものに変えられます（8文字以上、記号も使えます）。一度ここで変えると、以降は `.env` ではなく、ここで決めたパスワードが使われます。
- 一度ログインしたブラウザは、ログアウトするまでパスワードを聞かれません。パスワードを変えると、他のブラウザはログアウトされます。
- 忘れたときは、次のコマンドで `.env` の初期値に戻せます。

```
docker compose exec admin python db.py reset-password
```

### 他の端末から開く（スマホ・別の PC）

既定では、そのマシンの中（`127.0.0.1`）からだけ開けます。同じネットワークの他の端末から開くときは、`.env` を次のようにして、**必ずパスワードを設定**してください。

```
ADMIN_BIND=0.0.0.0
```

```
docker compose up -d
```

そのうえで、`http://<そのマシンのIPアドレス>:8501` を開きます。

> 管理画面は、インターネットに直接公開しないでください（通信が暗号化されません）。外から使いたいときは、Tailscale などの VPN を通すのがおすすめです。

## 最初の使い方

1. **「送信先」タブ**: 名前をつけて、Webhook URL を登録します（例: 「お知らせ」「雑談」）。「テスト送信」で、届くか確かめられます。
2. **「設定」タブ → 確認用 Webhook**: 「送れなかったときの確認通知」が届く先です。自分だけが見られる非公開チャンネルをおすすめします。
3. **「予約」タブ / 「誕生日」タブ**: 追加します。送信先は、1で登録した名前から選びます。

入力欄で Enter キーを押しても、保存や追加は実行されません。「追加する」「保存する」のボタンを押したときだけ動きます（押し間違い防止です）。

誕生日の送信時刻と、タイムゾーン（既定は `Asia/Tokyo`）は、「設定」タブで変えられます。

## 止まっていた間の扱い

マシンの停止などで、送る時刻を過ぎてしまった予約・誕生日の扱いを、1件ごとに選びます。

| 選択 | 動き |
| --- | --- |
| 確認通知 | 送らずに、確認用 Webhook へ「送れなかった」と知らせます。送るかどうかは、管理画面の「今すぐ送信」で自分が決めます（予約の既定） |
| 遅れて送る | 許容時間（設定タブ、既定6時間）以内なら、遅れてでも送ります。誕生日は、その日のうちなら送ります（誕生日の既定） |
| スキップ | 何もしません |

繰り返す予約は、止まっていた間の分をまとめて送り直すことはありません。次の予定は、いまより後で計算し直します。

## 更新

```
git pull
docker compose up -d --build
```

予約・誕生日・送信先などのデータは `data/` に残ります。古い形式のデータは、起動時に自動で新しい形式へ移ります。

## バックアップ

大事なデータ（予約・誕生日・送信先とその Webhook URL・設定）は、`data/scheduler.db` に入っています。**Git には入りません**（`.gitignore` で外してあります。Webhook URL は秘密情報だからです）。マシンが壊れると消えるので、バックアップを取っておいてください。

バックアップは3段階あります。

### 1. 自動バックアップ（設定は不要）

1日1回、`data/backups/scheduler-auto-日付.db` に自動で保存されます。最新14日分を残して、古いものから消えます。DBの壊れや、操作の間違いから戻すときに使えます。

### 2. 画面から操作

「設定」タブ → 「バックアップ」で、次ができます。

- **いますぐバックアップ**: その場で1つ作ります。
- **いまのデータをダウンロード**: `.db` ファイルを、自分の PC に保存します。
- **バックアップから復元する**: `.db` ファイルを選んで、データを置き換えます。置き換える直前の状態は、`data/backups/scheduler-before-restore-日時.db` に自動で残ります。

> ダウンロードしたファイルには Webhook URL がそのまま入っています。他の人に渡さず、安全な場所に保管してください。
> 復元すると、パスワードも、そのバックアップを作った時点のものに戻ります。

### 3. 別の場所へコピーする（機械ごと壊れたときのために）

自動バックアップは同じマシンの中にあるので、そのマシンが壊れたり、ディスクが飛んだりすると一緒に消えます。**`data/backups/` を、別のディスクや別のマシンへコピーしておくと安心です。**

外付けの SSD や USB メモリを使う例です（Linux）。`/mnt/ssd` は、ディスクをつないでいる場所に置き換えてください。

```
rsync -a ~/ink-scheduler/data/backups/ /mnt/ssd/ink-scheduler-backups/
```

毎日、自動でコピーするには、`crontab -e` に1行足します（毎日 4:30 の例）。

```
30 4 * * * rsync -a ~/ink-scheduler/data/backups/ /mnt/ssd/ink-scheduler-backups/
```

別のマシンへ送る場合は、`rsync -a ~/ink-scheduler/data/backups/ ユーザー名@相手のIP:ink-scheduler-backups/` のようにします。

### 復元のしかた

- **画面から（普通はこちら）**: 「設定」タブ → 「バックアップから復元する」で、ファイルを選びます。
- **画面が開けないとき（コマンド）**: バックアップのファイルを `data/` に置いて、次を実行します。

```
docker compose exec admin python db.py restore data/ファイル名.db
```

- **マシンごと壊れたとき**: 新しいマシンで「導入」の手順を行い、管理画面を開いてから、取っておいたバックアップを「バックアップから復元する」で読み込みます。予約も送信先も、元どおりになります。

コマンドで、いま手動バックアップを作ることもできます。

```
docker compose exec admin python db.py backup
```

## よくあるトラブル

| 症状 | 対処 |
| --- | --- |
| `address already in use`（ポートが使われている） | `.env` の `ADMIN_PORT` を別の番号（例: `8502`）にして、`docker compose up -d` |
| 予約の時刻が、ずれて送られる | 「設定」タブのタイムゾーンを確認します。ログの時刻は `.env` の `TZ` です |
| 管理画面で保存しようとすると、権限のエラーが出る | `.env` の `APP_UID` / `APP_GID` を、`id -u` / `id -g` の結果に合わせて、`docker compose up -d` |
| 送られていない気がする | 「履歴」タブで、送信・失敗・通知を確認します。コマンドなら `docker compose logs --tail 50 sender` |
| Webhook を作り直した | 「送信先」タブで、その送信先の URL を差し替えます（予約や誕生日は、そのまま使えます） |
| 送信先を削除できない | その送信先を使っている予約・誕生日があるためです。先に、別の送信先へ変えてください |

## 補足

- 管理画面は、Webhook URL を末尾4文字だけ表示します。履歴にも URL は残りません。
- 誕生日のメッセージは、メンション（`<@ID>`）した本人にだけ通知が届きます。名前の中の `@everyone` などは、通知されません。
- 履歴は、180日より古いものから自動で消えます。
- Discord の Webhook には、1回の本文が 2000 文字までという上限があります。
